# SOW delivery and acceptance model

- **Scope:** agreed asset classes, environments, supported integrations, exclusions and deliverables.
- **Discovery:** inventory baseline, source-of-truth ownership, dependencies and source data quality.
- **Architecture:** collection patterns, networking, security, telemetry governance and sizing.
- **Execution:** pilot, migration waves, approvals, deployment, rollback and coordination.
- **Validation:** dual-run checks for inventory, telemetry coverage, timeliness, service mapping, alert parity and owner signoff.
- **Handover:** runbooks, incident response, support boundaries, training and hypercare if in SOW.
- **Change control:** track out-of-scope requests separately and obtain written authorization.

Sample acceptance criterion: all in-scope critical services are discovered, required signals are visible within agreed latency, monitoring owners approve alert coverage, and rollback evidence is recorded.
